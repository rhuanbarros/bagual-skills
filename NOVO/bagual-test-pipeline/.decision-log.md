# Decision Log — bagual-test-pipeline

## 2026-05-27 — Step 3.5: Startup Smoke Test

**Problema identificado:** O pipeline executava `dotnet build` + unit tests (Step 3) e chegava ao E2E (Step 4) sem nunca tentar subir a aplicação. Erros de configuração em runtime — `Program.cs` mal configurado, serviço não registrado no DI, middleware inválido — passavam invisíveis porque compilam sem erro e unit tests usam mocks.

**Caso concreto que motivou:** `QualitorWrapper.McpServer` com `WithHttpTransport()` mal configurado. 193 unit tests passaram. `dotnet build` passou. App crashava ao iniciar.

**Decisão:** Adicionar Step 3.5 entre unit tests (Step 3) e E2E (Step 4).

**Comportamento do Step 3.5:**
- Detecta todos os .csproj RUNNABLE (ASP.NET Core / Exe) — exclui test projects
- Para cada um: `dotnet run --no-build` em background + polling HTTP (/health → /swagger → /) por até 30s
- FAILED (exit code != 0) → HALT com stderr completo
- PASSED (health endpoint responde) → continua
- INCONCLUSIVE (30s sem resposta, processo ainda vivo) → avisa e continua (E2E verifica depois)

**Alternativas rejeitadas:**
- Step em `story-processor.md` por story: muito granular, ruidoso para stories que não tocam startup
- Adicionar em `bagual-bmad-implement-quick-epic`: já chama `bagual-test-pipeline`, a mudança cascateia automaticamente

**Onde foi aplicado:** `references/workflow.md` em NovoEPA e qualitorwrapper (cópias independentes, edição manual aplicada em ambas).
