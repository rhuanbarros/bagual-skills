### Classification
Simple Workflow, as instructed. One linear pass over one shared document (design spec + epic
doc), fixed 8-step checklist, no resumable phases, no multi-session state beyond the final
`spec-gate-epic-<N>.md` artifact. Headless (`-H`) supported since this skill is meant to run
unattended before an epic reaches bmad-loop/bagual-epic-runner — with the explicit carve-out that
Step 5 (`Block If`) never auto-answers even in headless mode; it records a pending HALT instead.

### Customization
Not customizable — no `customize.toml`. Matches the majority of this project's `bagual-*` skills
(`bagual-epic-runner`, `bagual-tickets`, `bagual-gerente-geral`, `bagual-import-planilhas`,
`bagual-template-push`, `bagual-template-sync` all ship with fixed paths, no resolver step). Only
the QA-gate skills (`bagual-qa-builder`/`bagual-qa-run`/`bagual-qa-setup`) use `customize.toml` in
this project, and this isn't one of them — nothing in the brief suggested a team/personal override
surface was wanted here.

### No sub-agent dispatch
Chose to run the entire gate inline in the skill's own session — no `Agent`-tool dispatch
anywhere, including for Step 7's iterative Wiki grounding search. Rationale: Step 5's HALT needs
to talk to the owner directly in interactive mode, which an isolated sub-agent can't do; and the
simpler `bagual-tickets`/`bagual-import-planilhas` precedents in this project already run fully
inline without a fan-out. If a future revision finds Step 7's grounding search benefits from a
fresh, isolated context window, the anti-orphan rule (`model: "sonnet"` + `run_in_background:
false`, per `bagual-epic-runner/story-processor.md`'s banner) applies to that dispatch — noted in
SKILL.md's On Activation conventions in case that need arises later, but not exercised by this
build.

### Report language
SKILL.md/workflow.md prose and every generated artifact (`spec-gate-epic-<N>.md`, in-place spec
corrections) are English — the standard house phrase ("this skill's artifacts are English
regardless of `document_output_language`") used by the majority of `bagual-*` skills, not the
`bagual-tickets` deviation (which writes Portuguese ticket content by explicit local convention).
Rationale: the target documents this skill audits live in `_bmad-output/implementation-artifacts/`

Step 5 owner Q&A transcript is recorded verbatim, untranslated, in whatever language the owner

### `scripts/inventory_sweep.py` design
- stdlib-only (`re`, `pathlib`, `argparse`, `json`) — no external dependencies, no `uv`
  dependency block needed beyond `requires-python`.
- Whole-word match (`\b<entity>\b`) rather than plain substring — prevents a search for
  `expense_type` from false-positive-matching inside a longer identifier like
  `old_expense_type_backup`, while still catching every real reference (`.expense_type`,
  `expense_type,`, etc.). Verified by `test_whole_word_match_does_not_false_positive_on_substring`.
- File-kind classification (migration/seed/test/doc/code) uses a fixed priority order documented
  in the function's docstring — a migration under a `tests/` fixtures folder is still reported
  `migration` first (the schema-change risk dominates); a seed script with `test` in its name is
  still `seed` first (it writes real rows).
- Exit codes: `0` = swept successfully regardless of hit count (a zero-result sweep is a real,
  reportable finding, not a script failure); `2` = usage error (empty entity name, unresolvable
  repo root). This departs slightly from the generic script-standards template's "0=pass, 1=fail"
  framing — deliberately, since this script is a search tool, not a pass/fail gate; the gate
  judgment (finding used vs. not) belongs to the calling skill step, not the script.
- The missing `--include`/path-filter flag is the mechanical lock the brief specified as
  non-negotiable — verified by `test_no_include_or_path_filter_flag_exists` (asserts argparse
  rejects it, exit code 2) and `test_help_output_options_list_has_no_include_flag` (asserts the
  generated `options:` listing never grows one). Any future PR re-adding `--include` "for
  convenience" fails these tests loudly.
- Tests use `pytest` (PEP 723 `dependencies = ["pytest"]`, `uv run --with pytest pytest
  scripts/tests/test_inventory_sweep.py`), matching this project's existing script-test convention
  (`bagual-worktree/scripts/tests/*.py`), not bare `unittest`. All 9 tests pass locally
  (`uv run --with pytest pytest scripts/tests/test_inventory_sweep.py -v`).

## Session 2026-08-03 — Hardening pass (Gerente, reviewing the build)

**`--repo-root` had re-opened the exact hole the script was written to close.** The build gave
`inventory_sweep.py` a `--repo-root` flag (legitimately needed — the tests sweep a temp tree), but
nothing stopped a caller from passing `--repo-root frontend/src` and getting a silent partial
sweep. That is precisely the mistake that lost `expense_type` in Story 22.1: a grep scoped to
`frontend/src` with `--include="*.tsx"`, while the column actually lived in tests, seeds and
migrations. Removing the flag would have broken the tests; leaving it as-is left the guardrail
decorative.

**Decision:** keep the flag, make misuse impossible to miss. `detect_narrowed_scope()` walks the
root's ancestors and, if any of them is a real repository (contains `.git`), stamps a
`scope_warning` onto the result — surfaced in BOTH output modes (JSON field and a `⚠️` line at the
top of the human report). `workflow.md` Step 2 now instructs the gate to discard any result
carrying a non-null `scope_warning` and re-run unscoped, and records the calibration figure: a
correct repo-wide sweep for `expense_type` returns **405** occurrences (80 code / 128 test / 42
migration / 155 doc). A partial sweep can never support a "no consumers" conclusion.

Rejected: dropping `--repo-root` entirely (breaks the test suite's isolation), and hard-refusing a
sub-root (would block a legitimate deliberate narrow sweep — the point is that it can't happen
*silently*, not that it can't happen).

**Verified by failing test first**, per the project's standing rule that a test which never failed
proves nothing: neutralized `detect_narrowed_scope`'s ancestor walk →
`test_sweeping_a_subdirectory_of_a_repo_is_flagged_as_narrowed` failed (`assert None is not
None`); restored → 11/11 pass.
