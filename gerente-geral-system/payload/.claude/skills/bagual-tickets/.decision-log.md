# Decision Log — bagual-tickets

## Session 2026-07-07 — Build

**Origin.** User wanted a lightweight ticket-manager skill for the <PROJETO> project, distinct from epic/story planning (`sprint-status.yaml`) and from full requirements discovery (WDS for new features, `bmad-quick-dev`/`bmad-spec` for spec-readiness on bugs). Initial framing over-reached into full spec elicitation via `bmad-spec`/`bmad-agent-pm` — corrected by the user: this skill should stay minimal, only (1) a raw-completeness check (not a spec), and (2) verifying a reported bug actually exists and expanding the ticket to sibling occurrences of the same pattern found elsewhere in the codebase.

**Classification.** Simple Workflow, standalone (not module-based) — follows the `bagual-*` naming/location convention already used in this project (`bagual-worktree-creator`, `bagual-qa-run`, etc.), not the BMad-official `bmad-` prefix or the default `{project-root}/skills` output location. Built into `.claude/skills/bagual-tickets/`.

**Scope boundary (deliberate).** Explicitly does NOT do spec elicitation or feature-requirements discovery. Delegates: `/bmad-quick-dev` (its own clarify step covers most bugs), `/bmad-spec` (messy/multi-source or heavily expanded tickets), WDS Freya/Saga (new-feature requests), `/bmad-correct-course` (ticket conflicts with a recorded product decision). This boundary is the main reason the skill stays small — logged so a future edit doesn't creep it into a spec tool.

**Storage.** `{project-root}/project_controll/tickets/` — user's explicit choice (deliberately outside `_bmad-output/`, exact path as given by the user, not auto-corrected). Board index (`board.yaml`) + one markdown file per ticket, mirroring the existing `sprint-status.yaml` + per-story-file pattern in this project. Considered and rejected: (a) JSON storage — not diff-friendly, inconsistent with the rest of the project's artifacts; (b) the BMad Decision-Log Workspace pattern (one folder per run with `.decision-log.md`) — rejected because tickets are an ongoing collection across many independent invocations, not a single revisable artifact; each ticket instead carries its own lightweight `## Log` section.

**Invocation.** Explicit only (menu-driven: Adicionar/Board/Triar/Resolver). Organic/passive triggering (auto-detecting "tem um bug aqui" mid-conversation) was discussed and drafted, but the user decided against it for now given the over-broadening risk called out during design (BMad's own failure-mode list flags description over-broadening as a known failure with real cost). Can be added later as a description-trigger change if it proves worth the risk.

**Priority scheme.** Alta/Média/Baixa only, suggested by the skill during triage (heuristic: breaks a critical flow vs. cosmetic, how many locations the expansion check found) with user override — chosen over a Severity×Impact matrix (more precise but more upkeep) and over pure manual ordering (no automation value).

**Language.** Ticket content is written in Portuguese regardless of `document_output_language: English` in `{project-root}/_bmad/bmb/config.yaml` — that config value doesn't match actual practice; every real artifact in `_bmad-output/` (decisions, specs) is already in Portuguese.

**Headless.** Supported from the start (user's choice) — no confirmation prompts in headless mode; assumptions made without the user are logged in the ticket's own `## Log` section instead of a separate workspace decision log (there is no per-run workspace here, tickets ARE the persistent artifacts).

**Customization.** Declined (`customize.toml` not emitted) — single-project internal tool, not meant for distribution; matches `bagual-worktree-creator`'s precedent (no customize.toml) rather than `bagual-qa-run`/`bagual-qa-builder`'s (which have one).

**Scripts.** None. Next-ticket-ID generation and board.yaml read/update pass the "would an LLM do this correctly without being told?" test for a single-user tool at this scale — kept as plain prompt instructions instead of a script, matching how `sprint-status.yaml` is already maintained without a dedicated script in this project.
