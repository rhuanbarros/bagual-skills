# Decision Log — bagual-bmad-implement-quick-epic

## Session 2026-05-26 — Fast mode addition

### Context
User reported that the pipeline is sometimes slow due to the code-review correction loop (up to 2 iterations × review + dev-story correction). Asked for a "fast mode" without creating a duplicate skill.

### Decision: Single skill, two modes via `fast` argument
- Normal (default): create-story → dev-story → code-review loop (max 2 iterations)
- Fast: create-story → bmad-quick-dev (single-pass implement + inline review, no correction loop)
- Invocation: `/bagual-bmad-implement-quick-epic 2 fast`

**Rejected alternative — separate skill:** Would have duplicated workflow.md, story-processor.md, SKILL.md boilerplate. Avoided via mode flag approach.

**Rejected alternative — skip only code-review, keep dev-story:** Simpler but doesn't leverage bmad-quick-dev's unified intent→code flow. The user specifically asked about bmad-quick-dev.

### Decision: Keep create-story (Step A) in both modes
Step A creates the story spec file. Without it, bmad-quick-dev wouldn't have a detailed spec to work from. Speed gain in fast mode comes from eliminating the review correction loop, not from skipping spec creation.

### Decision: Deferred findings step (Step 4) unchanged in fast mode
Fast mode skips Step C (review loop) entirely, so no deferred findings are generated. The deferred-findings step is a no-op in practice for fast-mode runs (file won't exist or will be empty).
